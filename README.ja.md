# Quick Actions

[English](README.md) | 日本語

Claude Code の会話（トランスクリプト）で選択したテキスト、会話そのもの、そしてそのどちらも使わない単独の作業のためのアイコンアクションの Claude Code プラグインです。テキストを選択するとプロンプト下のヒント行にアイコンが並び、押すと選択テキストに対するアクション（翻訳・説明・要約・校正・コードの読み解き・根拠探し・データの変換など）や、今の会話に対するアクション（会話の要約・決定事項・次にやること・直前の回答の言い換え・コミットメッセージの下書きなど）、選択も会話も使わないアクション（タイマー・カレンダー・電卓・パスワード生成・雛形・リポジトリの概要など）を実行して、結果をペインに表示します。組み込みのアクションは 3 種類で計 311 個です。ヒント行には 1 種類ずつ並び、先頭のボタンで種類を切り替えます。何も選択していなくても `/quick-actions hint` でヒント行を出せ、`/quick-actions <id> [引数]` で ID を指定して直接実行できます（例: `/quick-actions timer 5m`）。引数を取るアクションは、ヒント行や ⋯ ダイアログから押したときも引数の入力画面で時間などを指定でき、タイマー類は結果欄のボタンで同じ引数のまま再実行できます。よく使うアクションほど前に並び、設定で先頭に固定（ピン留め）することもできます。ヒント行に並ばないものも含め、すべてのアクションは末尾の ⋯ から選べ、ダイアログの絞り込み欄に ID や名前を入力して探せます。表示と回答の言語は日本語と英語を切り替えられます（既定は Claude Code の言語設定・ロケールに合わせる）。

組み込みのアクションはすべて **[アクション一覧ページ](https://imahiro-t.github.io/quick-actions/?lang=ja)** で、カテゴリ別に検索・絞り込みしながら見られます（日本語・英語）。

## 動き

アクションは 3 種類あり、ヒント行には 1 種類ずつ並びます（[種類の切り替えボタン](#表示する種類の切り替え)で切り替えます）。

- **選択アクション**（`[アイコン]` で表示）: 選択したテキストに対して実行します（[選択アクションの一覧](#選択アクション)）
- **コンテキストアクション**（`<アイコン>` で表示）: 選択テキストを使わず、今の会話そのものを対象に、会話を引き継いだ分岐（fork）で実行します（[コンテキストアクションの一覧](#コンテキストアクション)）
- **コンテキストなしアクション**（単独、`{アイコン}` で表示）: 選択テキストも会話も使わずに実行します。タイマー・電卓・ID 生成のようにプラグインの中だけで計算するもの（ローカル実行）と、雛形やアイデア出しのようにモデルに頼むものがあります。`/quick-actions <id> <引数>` か、ヒント行・⋯ ダイアログから押したときに開く[引数の入力画面](#引数の入力画面)で引数を渡せ、引数なしなら既定値で動きます（[コンテキストなしアクションの一覧](#コンテキストなしアクション単独)）

同じアイコンが種類違いで使われていることがありますが（`[🧸]` と `<🧸>` と `{🧸}` など）、`[ ]`・`< >`・`{ }` で見分けられます。

1. トランスクリプトのテキストをマウスで選択する（何も選択していないときは [`/quick-actions hint`](#選択なしでヒント行を開くquick-actions-hint) を実行する）
2. プロンプト下にヒント行が出る。先頭に種類の切り替えボタン `[選択] <会話> {単独}`、続いて表示中の種類のアイコン、その後ろに ✕ と ⋯ が並ぶ。アイコンにマウスを重ねるとラベルが出る
   - 選択があるときは選択アクションを、選択がないときはコンテキストアクションを表示した状態で開く（[表示する種類の切り替え](#表示する種類の切り替え)）
   - 並ぶアイコンの数はヒント行の幅に合わせて変わる。種類の切り替えボタン・✕・⋯・行の左の権限モードの表示（`⏵⏵ auto mode on ·` など）の横に入る数だけ、`hintCount × 桁数 ÷ 80` を上限に並ぶ。80 桁で 2 個、100 桁で 3 個、160 桁で 10 個（[`hintCount`](#hintcount)）
   - 種類ごとの並び順は「[`actions`](#actions) で先頭に固定（ピン留め）したもの → 残りをよく使う順」。使うたびに使用回数を記録し、最近よく使うものほど前に来る（[使用回数の保存](#使用回数の保存)）
   - 初めて使うとき（ピン留めも使用履歴もないとき）は、どの種類でも[既定のセット](#actions)が先頭に来る。選択アクションは `[💡] [🌐] [📝] [🔎] [🔤] [🀄] ✕ ⋯`、コンテキストアクションは `<🧭> <✅> <📋> <❓> <🧸> <🌐> ✕ ⋯`、コンテキストなしアクションは `{⏳}` から
   - 並べ替えはセッションの開始時だけ。セッション中に使っても並びは動かないので、押そうとした位置がずれることはない
   - アクションのアイコン（どの種類でも）か ✕ を押すと、その選択についてはアイコンを隠す（別のテキストを選べばまた出る）。引数を取るコンテキストなしアクションのアイコンは、押すと引数の入力画面が開き、そこで実行したときにアイコンを隠す
   - Claude Code は、アイコンを押したときに選択を読めるよう、別の箇所をクリックしてハイライトが消えても直前の選択を覚えている（別のテキストを選ぶか、次のプロンプトやコマンドを実行するまで）。ハイライトが消えたことはプラグインに知らされない。そのため、どのアイコンも押さずにクリックで選択を外しただけでは選択アクションのアイコンは残る。使わないときは ✕ で閉じるか、`<会話>`・`{単独}` に切り替えてほかの種類を使う
   - Claude Code が「選択なし」と答えるようになると（次のプロンプトやコマンドの後など）、0.3 秒ほどでアイコンは消える。これは選択だけで出たヒント行の動きで、`/quick-actions hint` で開いたヒント行の閉じ方は[後述](#選択なしでヒント行を開くquick-actions-hint)のとおり
3. アイコンを押すと、右ペインの「Quick Actions」タブの先頭に結果が積まれる（ペインに残るのは新しい順に 20 件まで）。ペインを下へスクロールしていても、実行するとペインは先頭（最新の結果）まで戻る
   - 結果の見出しには、アイコンとラベルの後ろに、選択アクションなら選択テキストの引用、コンテキストアクションなら「今の会話」、コンテキストなしアクションならコマンドや引数の入力画面で渡した引数（引数なしなら「単独」）が出る
   - transcript の 1 行の中の選択に対して実行したアクションでは、結果にその行へスクロールして戻る「選択箇所に戻る」ボタンが付く（[「選択箇所に戻る」ボタン](#選択箇所に戻るボタン)）
   - フルスクリーン表示でターミナル幅が 110 桁以上ならペインは右側にドックし、それ未満ならプロンプトの上に表示される
   - ペインには常に「Quick Actions」（結果）と「アクションを選択」（⋯ ダイアログ）の 2 つのタブがあり、Esc 1 回で両方とも閉じる（[右ペインの 2 つのタブ](#右ペインの-2-つのタブ)）
   - ヒント行で引数を取るコンテキストなしアクション（`{⏳}` タイマーなど）を押すと、すぐには実行せず、右ペインの「アクションを選択」タブでそのアクションの[引数の入力画面](#引数の入力画面)を開く。空欄のまま Enter で既定値、入力して Enter でその引数で実行する。引数を取らないアクション（`{🏃}` ストップウォッチなど）は今まで通り押すとすぐ実行する
   - モバイルアプリなど入力欄が使えない環境では、引数の入力画面は出さず、押すとすぐ既定値で実行する。引数を渡すときは `/quick-actions <id> <引数>` を使う（[コマンド](#コマンド)）
4. ヒント行に並んでいないアクションは、末尾の ⋯ を押すと開く右ペインの「アクションを選択」タブから選べる（`/quick-actions` を ID なしで実行しても開く）。絞り込み欄に入力して探せる（[⋯ ダイアログとフィルタ検索](#-ダイアログとフィルタ検索)）

選択テキストそのものはヒント行に出しません（複数行の選択でヒント行が 2 行にならないように）。

### 表示する種類の切り替え

ヒント行の先頭には、種類ごとのボタン `[選択]`・`<会話>`・`{単独}` が並びます（英語表示では `[selection]`・`<context>`・`{standalone}`）。押すと、その種類のアイコンがヒント行に並びます。表示中の種類は太字で、ほかは薄い色で描きます。ボタンにマウスを重ねると、どのアクションを表示するかの説明が出ます。

- **開いたときの種類**: 実行の対象になるテキスト（選択、または `/quick-actions hint` が取り込んだテキスト）があれば選択アクション、なければコンテキストアクション。テキストがないときは `[選択]` ボタンは出ない
- **切り替えが続く間**: ヒント行が出ている間。新しい選択（それまでと違うテキスト）、`/quick-actions hint` の実行、✕、アクションの実行のあとは、開いたときの種類に戻る。まったく同じテキストを選び直しても新しい選択とはみなさないため、切り替えた種類のまま残る
- **ボタンがある理由**: Claude Code はハイライトが消えたあとも直前の選択を答え続け、消えたことをプラグインに知らせない。そのため、画面上の選択とクリックで外した選択を見分けられない。クリックで選択を外したのに選択アクションが並んだままのときは、`<会話>`・`{単独}` に切り替えて使う
- **幅が狭いとき**: 名前付きで描くとアクションが 2 個（`hintCount` の上限がそれより少なければその数）も入らないときは、ボタンを印だけ（`[ ]`・`< >`・`{ }`）で描く（マウスを重ねると説明が出る）。80 桁がこれに当たる。✕ と ⋯ に加えて印だけのボタンも収まらない幅では、ボタンを出さず、表示中の種類のままにする
- **ボタンの名前**: スクリーンリーダーやデスクトップアプリのネイティブボタンでは、描いている文字にかかわらず、表示するアクションの説明で読まれる。表示中のボタンはその旨も付く（例:「選択範囲へのアクション（表示中）」、英語表示では「Actions on the selection (shown)」）

### 右ペインの 2 つのタブ

右ペイン（幅の狭いターミナルではプロンプトの上）は、常に **「Quick Actions」**（結果）と **「アクションを選択」**（[⋯ ダイアログ](#-ダイアログとフィルタ検索)）の 2 つのタブで開きます。

- **前面に出るタブ**: ヒント行のアイコンを押したときは「Quick Actions」。ヒント行の ⋯、ID なしの `/quick-actions` からは「アクションを選択」が前面に出て、その絞り込み欄にキーボードが移る（Claude Code がキーボードを渡せる状態のとき）
- **「アクションを選択」でアクションを選ぶ**と、結果とともに「Quick Actions」が前面に出る。「アクションを選択」は閉じずに後ろに残り、絞り込み欄は空に戻るので、続けて選べる
- **閉じる**: 1 回の操作でペイン全体（2 つのタブ）が閉じる。Esc、どちらかのタブの閉じるマーク（ctrl+x x）、「アクションを選択」の「閉じる」ボタンのどれでもよい
  - 絞り込み欄に入力中の Esc も、欄を空にするのではなくペインを閉じる。欄を空にするには、横の「クリア」ボタンを押す（または文字を消す）
  - キーボードがプロンプトにあっても、アイドル中の空のプロンプトで Esc を押すとペインが（2 つのタブとも）閉じる
  - 閉じると、[時間経過のあるアクション](#時間経過のあるアクション)はすべて止まる。実行中のモデル呼び出しやサブエージェントは裏で続き、その回答は「Quick Actions」に残る（次にペインを開いたときに見える）
- 開き直したタブを前面に出さない Claude Code では、プラグインがそのタブを閉じて開き直して前面に出す。そのため、タブが一瞬閉じて開き直ることがある
  - キーボードが「アクションを選択」にある状態（一覧で選んだときや引数を入力したとき）で実行すると、Claude Code は開き直したタブよりもそのタブを前面に残す。そのためプラグインは 2 つのタブを閉じて「Quick Actions」が最後になる順に開き直し、結果を前面に出す。このときキーボードはプロンプトに戻る。続けて別のアクションを選ぶには「アクションを選択」タブをクリックする（または ctrl+x tab）。アイドル中の空のプロンプトで Esc を押すと、通常どおりペインが閉じる

### 選択なしでヒント行を開く（`/quick-actions hint`）

`/quick-actions hint` を実行すると、選択の有無にかかわらずヒント行を出せます。

- **何も選択していないとき**: コンテキストアクションとコンテキストなしアクションを同じ並び順で出す。コンテキストアクションを表示した状態で開き（初めて使うときは `<🧭> <✅> <📋> <❓> <🧸> <🌐> ✕ ⋯`）、`{単独}` でコンテキストなしアクションに切り替えられる。`[選択]` ボタンは出ない
- **テキストを選択しているとき**: 選択だけで出るときと同じく、すべての種類を出し、選択アクションを表示した状態で開く。コマンドを実行すると Claude Code はその選択を「選択なし」と答えるようになるため、コマンドを実行した時点の選択テキストを取り込んでおき、選択アクションはハイライトが消えたあとも、そのテキストに対して実行する

`hint` は引数を取りません（`/quick-actions hint foo` は `hint は引数を受け付けません: foo` と答えて何もしません）。

閉じ方は、選択だけで出たヒント行に揃えています。

- **✕ を押す**、または**ヒント行からアクションを実行する**（どの種類でも。ヒント行の ⋯ から開いたダイアログで選んだときも）
- **開いたあとに新しく作った選択が消える**: 開いている間にテキストを選ぶと、そのテキストに対してすべての種類が出る。その選択を Claude Code が「選択なし」と答えるようになると、0.3 秒ほどで閉じる

コマンドを実行した時点の選択はこれに当たりません。その選択の消失（コマンドの実行そのもので起きる）では閉じません。トレードオフとして、選択した状態で開いたヒント行は、元のテキストのハイライトが消えたあとも、✕ を押すかアクションを実行するまで残り、選択アクションはそのテキストに対して動きます（上の「クリックで選択を外してもアイコンは残る」のと同じ種類の動きです）。また、開いたあとに取り込んだのとまったく同じテキストを選び直しても新しい選択とはみなさないため、その選択が消えても閉じません。✕ で閉じてください。

### ⋯ ダイアログとフィルタ検索

ヒント行の末尾の ⋯ を押すか、`/quick-actions` を ID なしで実行すると、すべてのアクションから選ぶダイアログが開きます。これは右ペインの「アクションを選択」タブで、「Quick Actions」タブより前面に出ます（[右ペインの 2 つのタブ](#右ペインの-2-つのタブ)）。

- アクションは、ヒント行と同じ順に `[アイコン] ラベル`・`<アイコン> ラベル`・`{アイコン} ラベル` で並ぶ。一覧の上には種類の凡例（`[ ] 選択  < > 会話  { } 単独`）が出る
- 何も選択していないときに開いたダイアログ（選択なしで実行した ID なしの `/quick-actions`、または選択なしで `/quick-actions hint` を実行して開いたヒント行の ⋯）には、コンテキストアクションとコンテキストなしアクションだけが並び、凡例も `< > 会話  { } 単独` になる
- 一覧はボタンの並びで、ダイアログを開いた時点で表示される（開く操作は要らない）
- 一覧はペインの高さいっぱいに表示する。並びの先頭から、ペインに収まる件数だけ並べ（2 行に折り返す長いラベルは 2 行と数える）、ターミナルのサイズを変えると並べ直す（縮めてから元に戻したときも、高さいっぱいの表示に戻る）。それより多いときは、一覧の下に `ほか N 件は絞り込みで表示` と出るので、絞り込み欄で探す
- 選んだ選択アクションは、ダイアログを開いたときに選択していたテキストに対して実行する（ペインを開いたまま選択し直したときは、その新しいテキストに対して実行する）。コンテキストアクションは会話に対して実行する。コンテキストなしアクションは、引数を取るものなら一覧が[引数の入力画面](#引数の入力画面)に切り替わり、引数を取らないものはすぐ実行する。結果は前面に出た「Quick Actions」タブに表示する。ダイアログは閉じずに後ろに残り、そのテキストを保ったまま、絞り込み欄だけ空に戻る
- 絞り込み欄から Tab か ↓ で先頭のアクションへ移り、↑↓（または Tab / Shift+Tab）でアクション間を移動して、Enter でフォーカスのあるものを実行する。末尾のアクションで ↓ を押すと「閉じる」ボタンへ、先頭のアクションで Shift+Tab を押すと絞り込み欄へ戻る。クリックでも選べる。Esc と「閉じる」ボタンでは、何も実行せずにペイン全体（2 つのタブ）を閉じる
- プロンプトに入力中のテキストがあるときは、ダイアログにキーボードが移らない（モバイルアプリ以外ではダイアログに案内が出る）。クリックで選ぶか、入力欄を空にしてから開き直す（⋯ を押すか、実行と同時に入力欄が空になる `/quick-actions` で）

**絞り込み欄（フィルタ検索）**: 一覧の上に「絞り込み（ID・名前・種類）」の入力欄があり、開いたときはここにキーボードが移ります（開くたびに空から始まります）。入力するたびに一覧が絞り込まれます。

- **対象**: アクションの ID、ラベル（表示言語に関係なく日本語と英語の両方）、種類の名前（`選択`・`会話`・`コンテキスト`・`単独`・`コンテキストなし`・`selection`・`context`・`standalone`・`none`）
- **一致のしかた**: 部分一致。空白（半角・全角）で区切った語はすべてを含むもの（AND）だけが残る。全角と半角、大文字と小文字、カタカナとひらがなは区別しない（`ﾀｲﾏｰ`・`たいまー`・`ＴＩＭＥＲ` でも `timer` が見つかる）
- **種類で絞る**: `[`（または `[]`）・`<`（または `<>`）・`{`（または `{}`）を 1 語として書くと、それぞれ選択・コンテキスト・コンテキストなしアクションだけに絞る（例: `{ 時刻`）。違う種類の印を 2 つ書くと何も一致しない
- 並び順はそのまま。ただし ID が入力全体と一致するアクションは先頭に来る
- **Enter** で、絞り込んだ結果の先頭のアクションを実行する（欄の横に「先頭を実行」と出る。一致するものがないときは「一致なし」と出て、Enter では何も実行しない）
- 欄に文字があるときは横に「クリア」ボタンが出て、押すと欄を空にしてすべてを並べ直す（文字を消しても同じ）
- 絞り込み欄から一覧へキーボードを移すと（Tab か ↓）、↑↓ と Enter で一覧から選べる
- **モバイルアプリ**では絞り込み欄は出ず、すべてのアクションが上限なくボタンで並ぶ（タップで選ぶ）
- [`paneTheme`](#panetheme) が `light` / `dark` のときも、絞り込み欄と一覧の動きは同じで、ボタンを配色の色で描く
- **Claude が質問している間**（AskUserQuestion）は、ペインは閉じて開けない（次節）

### 質問ダイアログ（AskUserQuestion）の表示中

Claude の質問ダイアログ（AskUserQuestion）が出ている間は、ダイアログがキーボードを握り、プロンプトも消えます。Claude Code はこの間ペインにキーボードを渡さず、タブも切り替えられないため、Quick Actions は使えないようにしています。

- **質問が出たとき**: 右ペインは 2 つのタブとも閉じる。閉じるボタンで閉じたときと同じく、実行中のタイマーなど時間経過のあるアクションは止まる
- **質問の表示中**: ヒント行は出ず、`/quick-actions` も何も実行しない（`質問ダイアログの表示中は Quick Actions を使えません。` と答える）
- **質問に回答するかキャンセルしたあと**: いつもどおり使える。閉じたペインは自動では開き直さない

### 「選択箇所に戻る」ボタン

ペインを開くと、Claude Code の表示上は選択が外れて見えます。結果がどの箇所に対するものかをたどれるように、transcript の 1 行の中で選択して実行したアクションでは、結果に「**選択箇所に戻る**」ボタンを付けます。押すと transcript をその行までスクロールします（画面の中央に来るように）。対象になる行は、自分のメッセージ、Claude の回答、ツールの呼び出しとその結果、ツール呼び出しのまとまり、ツールの進捗表示、コマンドの出力、お知らせ、ターンの所要時間の行、質問ダイアログ（`AskUserQuestion`）です。

- transcript の表示は Claude Code が描くままにし、行にも選択した語句にも印は付けない。Claude Code がプラグインに知らせるのは選択を含む行だけで、行の中のどこを選んだかは知らせない。また、Claude Code が描く行（回答の Markdown、ツールの出力、自分のプロンプト）の一部にだけ色を付けるには、プラグインが行を自分で描き直すしかなく、本来の表示が失われる。行全体に色を付けても、どの語句を選んだのかは分からないため、行わない
- ボタンは結果ごとに付く（1 つの選択に 2 つのコマンドを実行すると結果は 2 つになり、それぞれにボタンが付く）。結果がペインにある間は残り、ペインを閉じても、別のアクションを実行しても、プラグインが再読み込みされても消えない。その結果がペインの 20 件から押し出されたときに一緒に消える
- その行が transcript に残っていないときは、押しても何も起きない

次の場合はボタンが出ません。アクションの実行自体はこれまでどおり動きます。

- 選択が複数の行にまたがっている、または transcript の外（ペイン、プロンプト、ヒント行、ダイアログ）にある。Claude Code が行を知らせない
- コンテキストアクションやコンテキストなしアクションの結果（選択に対して動くものではない）

ボタンの処理は Claude Code の中だけで行い、何も送信しません。

#### 引数の入力画面

引数を取るコンテキストなしアクション（[一覧](#コンテキストなしアクション単独)の「引数」の列が「なし」でない組み込みのものと、[`customActions`](#customactions) で `target` を `none` にしたもの）を ⋯ ダイアログで選ぶと（一覧からでも、絞り込み欄の Enter でも）、ダイアログが一覧からそのアクションの引数の入力画面に切り替わります。ヒント行でそのアイコンを押したときや、タイマー類の結果欄の「時間を指定」などのボタンを押したときも、右ペインの「アクションを選択」タブがこの画面で開きます。

- 画面には、アクションのアイコンとラベル、引数の書き方と例（例: `時間（1 秒〜24 時間。例: 25m, 90s, 1h30m, 5:00。省くと 25 分）`）、空欄で実行したときの動き（`空欄で Enter: 既定値（25m）で実行`。既定値のないものは `空欄で Enter: 引数なしで実行`）、入力欄、「戻る」と「閉じる」のボタンが並ぶ。開いたときは入力欄にキーボードが移る
- **空欄のまま Enter**（または「実行」）で既定値で実行し、**入力して Enter** でその引数で実行する。書き方は `/quick-actions <id> <引数>` の引数と同じ
- **書き方が正しくないとき**（`timer` に `99h` など）は何も実行せず（使用回数も数えない）、入力画面に `timer の引数が正しくありません: 99h（時間（1 秒〜24 時間。…））` と、コマンドで書いたときと同じ文言のエラーを出す。入力した値はそのまま残るので、直して Enter すれば実行できる。エラーの表示は次に Enter するまで残る
- **Esc**（または「戻る」）で、何も実行せずにアクションの一覧に戻る（絞り込み欄の文字はそのまま残り、キーボードは絞り込み欄に戻る）。一覧に戻ってからもう一度 Esc を押すとペイン全体（2 つのタブ）が閉じる。タブの閉じるマーク（×）も、入力画面では 1 回目は一覧に戻る。「閉じる」ボタンはその場でペイン全体を閉じる
- 入力画面で実行すると、タブは一覧に戻り（絞り込み欄は空に、テキストはそのまま）、結果を前面に出た「Quick Actions」タブに積む。結果の見出しには入力した引数（空欄なら「単独」）が出る。ヒント行から開いたときは、実行したときにその選択のアイコンを隠し、`/quick-actions hint` で開いたヒント行なら閉じる
- **モバイルアプリ**など入力欄が使えない環境では入力画面を出さず、これまで通り選んだら（押したら）すぐ既定値で実行する

### 時間経過のあるアクション

`timer`・`stopwatch`・`pomodoro`・`countdown-to`・`breathing`・`eye-rest` は、結果がすぐに出るのではなく、ペインの中で時間とともに表示が変わります（[タイマー類](#タイマー類)）。

- ペインの結果の欄に残り時間や経過時間が出て、その下に「停止」ボタンが出る。押すとその場で止まり、`停止しました（経過 mm:ss）` と表示する
- 終わったあと・止めたあと（同時実行の上限で失敗したときや、プラグインの再読み込みで止まったときも）は、「停止」ボタンの代わりに次のボタンが出る
  - **もう一度**（6 つすべて）: 前回と同じ引数で実行し直す（引数なしで実行したものは引数なしで）。新しい結果としてペインの先頭に積み、同時に動かせる数の上限などは普通に実行したときと同じ
  - **引数を指定するボタン**（引数を取る `timer`・`pomodoro`・`countdown-to`・`breathing`）: 前回の引数を入れた[引数の入力画面](#引数の入力画面)を開く。ラベルは引数に合わせて、`timer` は「時間を指定」、`pomodoro` は「回数を指定」、`countdown-to` は「時刻を指定」、`breathing` は「種類を指定」。モバイルアプリなど入力欄が使えない環境では出ない（「もう一度」だけが出る）
- 右ペインを閉じると（Esc、どちらかのタブの閉じるマーク、「閉じる」ボタンのどれでも 2 つのタブとも閉じる）、動いているものはすべて止まる（それぞれ「停止しました（経過 …）」になる）。ペインの結果が 20 件を超えて古い結果が押し出されたときや、設定の変更などでプラグインが再読み込みされたときも止まる
- 同時に動かせるのは 5 個まで。6 個目を実行すると `同時に動かせるのは 5 個までです。停止してから実行してください` と出て、その実行は失敗になる
- 最長 24 時間。それを過ぎると止まる（`stopwatch` は自分では終わらないので、停止するか 24 時間で止まる）
- 最後まで動いて終わったときはトーストで知らせる（例: `⏳ タイマー 25:00 が終了しました`）。停止ボタンやペインを閉じて止めたとき、24 時間で止まったときはトーストを出さない
- タイマーの時間は `/quick-actions timer 5m` のように引数で渡すか、ヒント行・⋯ ダイアログで押したときの引数の入力画面で指定する。引数なし（空欄）は 25 分。書き方は `90s`・`5m`・`1h30m`・`5:00`（分:秒）・`1:30:00`（時:分:秒）・数字だけ（分）で、1 秒から 24 時間まで

### 送信されるもの

アクションの種類と実行方式によって、外へ送るものが違います。

- **ローカル実行のアクション**（[アクション一覧](#アクション一覧)で方式が「ローカル」のもの。選択アクションの `count-text`・`format-json`・`base64-decode`・`decode-jwt`・`hash-text` など 16 個と、コンテキストなしアクションのタイマー類・時刻と暦・乱数と生成・計算と換算・早見表の 50 個）は、プラグインの中だけで計算します。モデルを呼ばず、何も外部へ送らず、ファイル・ネットワーク・シェルにも触れません。ローカル実行の選択アクションも、選択テキストをどこにも送りません
- **選択アクション**（ローカル実行以外）: アイコンや ⋯ ダイアログのアクションを押すか、`/quick-actions <id>` を実行したときだけ、選択テキストを Claude Code 経由でモデル（Anthropic API など、そのセッションが使っているモデル）に送ります。選択しただけ・⋯ ダイアログを開いただけ・`/quick-actions hint` を実行しただけでは送りません
- `fork` 方式の選択アクション（💬 Claudeに聞く と 🧾 根拠を説明）は、選択テキストに加えて現在の会話の内容もモデルに渡します
- **コンテキストアクション**は、押したとき、または `/quick-actions <id>` でその ID を実行したときに、選択テキストは送らず、現在の会話（セッションの fork）をモデルに渡します。それまでの会話の内容（プロンプト、Claude の回答、ツールの結果、読み込んだファイルの内容）がすべて含まれます。セッションで次のターンを送るときと同じです
- **コンテキストなしアクション**のうちモデルを使うもの（方式が `complete` か `subagent` のもの）は、アクションのプロンプトと引数だけをモデルに送ります。選択テキストも会話も送りません（選択した状態で実行しても、その選択は使わずにアイコンを隠すだけです）。引数は `/quick-actions <id> <引数>` か引数の入力画面で書いたときにだけ、書いたとおりに送ります。書かなかったときは、既定値のあるアクションはその既定値（`gitignore-template` の `node` など）を、ないアクションは引数なしとして送ります
- **リポジトリ調査**（`repo-overview` など `repo-` で始まる 7 個）は、作業ディレクトリのリポジトリを読み取り専用のツール（Read / Grep / Glob）で読むサブエージェントです。読んだファイルの内容はモデルに渡ります。ファイルの変更やコマンドの実行はしません
- 表示言語を自動判定する（`language` が `auto` の）ときだけ、Claude Code の設定（`language`）と環境変数 `LC_ALL` / `LC_MESSAGES` / `LANG` を読みます。値は言語の判定にだけ使い、どこにも送りません
- 選択テキストは指示ではなく対象のテキストとして渡しますが、Web ページやツールの出力など信頼できないテキストを選ぶと、回答がその中の指示に引きずられることがあります。特に `fork` 方式の 💬 Claudeに聞く と 🧾 根拠を説明 は、会話の文脈と合わせて選択テキストを扱うため影響を受けやすくなります（🧾 根拠を説明 は選択テキストを Claude の発言として扱い、会話の文脈で推論します）。なお、組み込みの `complete` 方式のアクションはツールを持たず、`subagent` 方式のアクションが使えるのは読み取り専用のツール（Read / Grep / Glob）か、Web を調べるツール（`WebSearch` / `WebFetch`）だけです。どちらもファイルの書き込みやコマンドの実行はできません
- **Web を調べるアクション**（📚 Webで裏どり `web-check`、📘 公式ドキュメント `official-docs`、🚑 エラーを調べる `search-error`、📦 パッケージ情報 `package-info`）は、選択テキストを外部へ送ります。選択テキストの語句を Web 検索サービスへの検索クエリとして送り、選択テキストに書かれた URL や、検索結果に出てきた URL のページを取得します。ファイルを読むツールを持たないため、検索クエリや URL にリポジトリの内容が混ざることはありません。検索クエリは選択テキスト由来、取得先は選択テキスト中の URL か検索結果の URL です（プロンプトでも検索クエリを選択テキストだけから作り、取得先をこれらの URL に限るよう指示していますが、この点はモデルがそれに従うことに依存します）。取得した Web ページに書かれた指示（プロンプトインジェクション）に、回答や、次に検索・取得する内容が引きずられることがあります。ファイルの変更やコマンドの実行はできないため、影響はペインの回答にとどまります。送るのは、ヒント行や ⋯ ダイアログでそのアクションを押したとき、または `/quick-actions <id>` で実行したときだけです。初めて使うときの並びには入りませんが、⋯ ダイアログからいつでも選べ（絞り込み欄に `web-check` などと入力する）、使うとよく使う順でヒント行に出ることがあります（並びから外す設定はありません）。検索・取得ができるかどうかは、Claude Code の `WebSearch` / `WebFetch` の権限設定にもよります
- [`customActions`](#customactions) で自分で追加したアクションも、種類に応じて同じように送ります（選択アクションは選択テキストを、コンテキストアクションは会話を、コンテキストなしアクションはプロンプトと引数を）。`WebFetch` / `WebSearch` を許したカスタムのサブエージェントは、選択テキスト・引数や読んだファイルの内容（リポジトリの外のものも含む）を外部のサイトへ送り得ます（選択テキストに紛れた指示に誘導されて送ることもあります）。コマンドの実行やファイルの変更ができるツール（`Bash` / `Write` / `Edit` など）は受け付けません（[設定から追加する](#設定から追加するcustomactions)を参照）

### 使用回数の保存

- ヒント行の並び順のために、アクションごとの使用回数を、Claude Code がこのプラグイン専用に用意するローカルの保存領域（`$.store`。Claude Code の設定ディレクトリ内のファイル）に保存します。外部へは送りません
- 保存するのはアクションの ID ごとの使用スコアと最後に使った時刻だけで、選択テキスト・引数・結果は保存しません
- スコアは使うたびに 1 増え、30 日で半分になります（昔よく使ったものがいつまでも前に残らないように）
- 外したカスタムアクションのスコアは並びに影響しません（定義を戻したときのために残ります）。使用回数をリセット・閲覧する UI はありません

## インストール

Claude Code のターミナルセッションのプロンプトで次を実行します（`<owner>/<repo>` はこのリポジトリを公開した GitHub の `オーナー/リポジトリ名` に置き換えてください）。

```
/plugin install quick-actions --marketplace <owner>/<repo>
```

1. `Add marketplace?` と聞かれたら `y`
2. プラグインの詳細が出たらスコープを選ぶ（ユーザースコープなら以後のすべてのセッションで有効）
3. 設定画面で `actions`（先頭に固定したいアクション。空のままならよく使う順）、`hintCount`（80 桁のヒント行に並べる数。既定 6）、`language`（既定 `auto`）と `paneTheme`（ペインの配色。既定 `auto`）を選ぶ。`customActions`（自分で追加するアクション）は空のままで構いません
4. `Installed quick-actions. Plugin is now active.` と出れば、そのセッションからすぐ使えます

## 設定（userConfig）

### `actions`

ヒント行の先頭に固定（ピン留め）するアクションの ID を、固定したい順にカンマ区切りで書きます。書かなかったアクションも、その後ろによく使う順で並び、⋯ ダイアログからも選べます。

`/config` の `quick-actions` の `actions` に、例えば次のように入力します。

```
explain,translate-ja,summarize,timer
```

コマンドラインから設定する場合:

```sh
echo '{"actions":"explain,translate-ja,summarize,timer"}' | claude plugin configure quick-actions@quick-actions --values-stdin
```

`settings.json` に直接書く場合（キーは `<プラグイン名>@<マーケットプレイス名>`）:

```json
{
  "pluginConfigs": {
    "quick-actions@quick-actions": {
      "options": { "actions": "explain,translate-ja,summarize,timer" }
    }
  }
}
```

- **未設定・空のとき**: ピン留めはなしで、すべてをよく使う順に並べます。使用履歴がない初回は、既定のセット `explain,recap,translate-ja,decisions,summarize,code,timer` を先頭に、残りを定義順（[選択アクション](#選択アクション) → [コンテキストアクション](#コンテキストアクション) → [コンテキストなしアクション](#コンテキストなしアクション単独)の順）に並べます。ヒント行では、どの種類も既定のセットのうちその種類のものが先頭に来ます。選択アクションは `[💡] [🌐] [📝] [🔎]`、コンテキストアクションは `<🧭> <✅>`、コンテキストなしアクションは `{⏳}` です
  - 使用回数が同じ・まだ使っていないアクションは定義順です。そのため、何か 1 つでも使うと、既定のセットを先頭にする並びはなくなり、使ったもの → 残りを定義順（たとえばコンテキストアクションを使ったあとの選択アクションは `[🌐] [🔤] [🀄] …`）になります。既定のセットを前に置き続けたいときは `actions` に書いてください
- **どの種類でも**: コンテキストアクションの ID（`recap`、`handoff` など）やコンテキストなしアクションの ID（`timer`、`calc` など）も、選択アクションの ID と同じようにピン留めでき、混ぜて好きな順に書けます。ヒント行では、ピン留めしたものがそれぞれの種類の先頭に来ます（`explain,recap` なら、選択アクションでは `[💡]`、コンテキストアクションでは `<🧭>` が先頭）。⋯ ダイアログの一覧では、書いた順に先頭に並びます
- **存在しない ID**: 無視します（エラーにはなりません）。有効な ID が 1 つも残らなければ、ピン留めなし（空のときと同じ）になります
- **自分で追加したアクション**: [`customActions`](#customactions) の有効な定義の ID も、標準のアクションと同じようにここに書けます
- **ID が変わったもの・外したもの**: [ID の変更](#id-の変更)を参照してください。古い ID を書いたままの場合は、存在しない ID と同じく無視されます
- 前後の空白・大文字小文字の違いは無視し、同じ ID を重ねて書いたときは最初の 1 つだけを使います
- 1 つの種類のピン留めがヒント行に並ぶ数（[`hintCount`](#hintcount)）より多いときは、その先頭から並ぶだけをヒント行に並べ、残りは ⋯ から選びます

### `hintCount`

80 桁のヒント行に並べるアクションの数です（既定 `6`）。残りは末尾の ⋯ から選べます。1 以上の整数を書きます。空・`0`・負の数・小数・数字以外は既定の 6 として扱います。

実際に並ぶ数は、ヒント行の幅に合わせて変わります。

- **幅に比例した上限**: `hintCount × 桁数 ÷ 80`（切り捨て、最低 1）。既定の 6 なら 120 桁で 9 個、160 桁で 12 個。これは上限で、実際には収まる数だけ並ぶ
- **収まる数まで**: 種類の切り替えボタン・✕・⋯・行の左の権限モードの表示と合わせて 1 行に収まる分だけ、先頭から数える。はみ出すことも、ボタンが 2 行に分かれることもない。入りきらないときは数を減らし、1 個も収まらない幅では 1 個も並べない。✕ と ⋯ は常に残り、すべてのアクションは ⋯ から選べる。万一見込みより幅が足りなくても、切れるのはアクションの並びの右端だけで、種類の切り替えボタン・✕・⋯ は欠けない
- **ボタンは描かれる幅で数える**: ボタンは `[ ラベル ]` と間を空けずに並べて描かれるので、ラベルに枠の 4 桁を足して数える
- **実際に並ぶ数**（既定の 6、選択があり、アイコンが絵文字 1 つの場合）: 80 桁で 2 個（種類の切り替えは印だけ）、100 桁で 3 個（英語では種類の切り替えを印だけにして 4 個）、160 桁で 10 個（英語では 8 個）。60 桁では種類の切り替えボタンを出さずに 2 個、45 桁では 0 個で ✕ と ⋯ だけになる
- **ドックしたペインの横**: ペイン（このプラグインのものもほかのプラグインのものも）が右側にドックしている間は、ペインの幅を引いたトランスクリプトの幅で数える
- **権限モードの表示の横**: 行の左には Claude Code が権限モード（shift+tab で切り替わる `⏵⏵ auto mode on ·`、`⏵⏵ accept edits on ·`、`⏸ plan mode on ·` など）を描き、行の左右に 2 桁ずつ余白がある。どのモードかはプラグインから分からないため、最も長い `⏵⏵ bypass permissions on ·` に合わせて常に 30 桁を引く
- 絵文字の表示幅はターミナルによって少し違うため、絵文字を含むアイコン 1 個あたり 1 桁の余裕を見ている
- 幅が分からないときは、従来どおり `hintCount` 個を並べる

```sh
echo '{"hintCount":"8"}' | claude plugin configure quick-actions@quick-actions --values-stdin
```

```json
{
  "pluginConfigs": {
    "quick-actions@quick-actions": {
      "options": { "actions": "explain,translate-ja", "hintCount": "8" }
    }
  }
}
```

ほかの設定と同じく、`/config` で変えればすぐ反映され、`claude plugin configure` や settings.json で変えた場合は Claude Code を再起動してください。

### `language`

ヒント行のラベル・ペイン・⋯ ダイアログ・コマンドのメッセージ・トーストの表示言語と、各アクションの回答言語を選びます。

| 値 | 動き |
| --- | --- |
| `auto`（既定） | Claude Code の `language` 設定 → `LC_ALL` → `LC_MESSAGES` → `LANG` の順に見て、日本語と判定できれば日本語、それ以外・判定できなければ英語 |
| `ja` | 日本語 |
| `en` | 英語 |

- Claude Code の `language` 設定（例: `"japanese"`、`"日本語"`、`"ja"`）があれば、それだけで決めます（ロケールは見ません）。日本語以外の言語名なら英語です
- ロケールは最初に値のある変数を使い、`ja` / `ja_JP.UTF-8` のように `ja` で始まれば日本語です（`C`・`POSIX`・`en_US.UTF-8` などは英語）
- 未知の値・空の値は `auto` として扱います
- 翻訳のアクションは訳す先の言語が固定です（`translate-ja` は常に日本語へ、`translate-en` は常に英語へ、`translate-zh` などはそれぞれの言語へ。`easy-japanese` は常にやさしい日本語で書き直します）。ラベルだけが表示言語に合わせて変わります（英語表示では「To Japanese」「To English」など）。直前の回答を訳す `translate-last`・`translate-last-en`・`translate-last-ja` も、訳す先は `language` より優先します
- ⋯ ダイアログの絞り込みは、表示言語に関係なく日本語と英語の両方のラベルで探せます
- 結果のタブのタイトル「Quick Actions」は製品名なので、どちらの言語でもそのままです。⋯ ダイアログのタブ「アクションを選択」は、英語表示では「Select an action」です

コマンドラインや settings.json で設定する場合:

```sh
echo '{"language":"ja"}' | claude plugin configure quick-actions@quick-actions --values-stdin
```

```json
{
  "pluginConfigs": {
    "quick-actions@quick-actions": {
      "options": { "actions": "explain,translate-ja,summarize,timer", "language": "ja" }
    }
  }
}
```

`/config` から変えると、プラグインが再読み込みされてすぐ反映されます（`claude plugin configure` や settings.json で変えた場合は Claude Code を再起動してください）。`auto` の判定はプラグインの読み込みごとに 1 回なので、実行中に Claude Code の言語設定やロケールを変えた場合も、再読み込みか再起動で反映されます。

### `paneTheme`

右側に表示される結果ペイン（ドック表示）と ⋯ ダイアログの配色です。

| 値 | 動作 |
| --- | --- |
| `auto`（既定） | Claude Code のテーマに従います（背景は Claude Code が塗り、文字はテーマの色で描きます） |
| `light` | テーマに関係なく、固定のライト配色（背景 `#fafafa`）と専用の文字色で描きます |
| `dark` | テーマに関係なく、固定のダーク配色（背景 `#1e1e1e`）と専用の文字色で描きます |

- ターミナルとテーマの明暗が食い違う環境（ダークなターミナルでライトテーマなど）や、ペインだけを好みの明暗で見たいときに `light` / `dark` を選んでください
- どちらの配色も、見出し・本文・エラー・補助テキストの文字色は背景色に対してコントラスト比 4.5:1 以上（WCAG AA）です。256 色のターミナル（Terminal.app など）で最も近い色に丸められた場合も 4.5:1 以上を保ちます。16 色のターミナルではより粗い近似色で描かれるため、比が下がることがあります
- `light` / `dark` のとき、⋯ ダイアログのアクションのボタンを配色の本文の色で描きます。絞り込み欄と一覧の動きは配色なしのときと同じです
- 時間経過のあるアクションの「停止」ボタンも、この配色で描きます
- インライン表示（ターミナル幅 110 桁未満）は対象外で、設定に関係なくターミナルの配色のままです
- 不明な値や空の値は `auto` として扱います
- ペインの外周には、プラグインの描く範囲の外として Claude Code がテーマ色の細い縁を残すことがあります

コマンドラインからは次のように設定します。

```sh
echo '{"paneTheme":"dark"}' | claude plugin configure quick-actions@quick-actions --values-stdin
```

他の設定と同じく、`/config` から変えるとすぐ反映されます（`claude plugin configure` や settings.json で変えた場合は Claude Code を再起動してください）。

### `customActions`

自分で追加するアクションの定義を、JSON の配列として 1 つの文字列で書きます（既定は空）。項目と例は[設定から追加する](#設定から追加するcustomactions)を参照してください。有効な定義は、標準のアクションと同じくヒント行（よく使う順）に並び、⋯ ダイアログから選べます（新しく追加したものは組み込みの後ろに並ぶため、一覧に収まる件数より後ろにあるあいだは、絞り込み欄に ID かラベルを入力して選びます）。`actions` に ID を書くと先頭に固定できます。`/quick-actions <id>` でも実行できます。

`/config` の `quick-actions` の `customActions` に、配列を 1 行で入力します。例:

```
[{"id":"pirate","icon":"🦜","label":{"ja":"海賊風に言い換え","en":"Pirate talk"},"kind":"complete","model":"haiku","prompt":"Retell the selected text the way a pirate would."}]
```

コマンドラインから設定する場合（値は文字列なので、中の引用符をエスケープします）:

```sh
claude plugin configure quick-actions@quick-actions --values-stdin <<'EOF'
{"actions":"explain,pirate","customActions":"[{\"id\":\"pirate\",\"icon\":\"🦜\",\"label\":{\"ja\":\"海賊風に言い換え\",\"en\":\"Pirate talk\"},\"kind\":\"complete\",\"model\":\"haiku\",\"prompt\":\"Retell the selected text the way a pirate would.\"}]"}
EOF
```

`settings.json` に直接書く場合も、同じようにエスケープします:

```json
{
  "pluginConfigs": {
    "quick-actions@quick-actions": {
      "options": {
        "actions": "explain,pirate",
        "customActions": "[{\"id\":\"pirate\",\"icon\":\"🦜\",\"label\":{\"ja\":\"海賊風に言い換え\",\"en\":\"Pirate talk\"},\"kind\":\"complete\",\"model\":\"haiku\",\"prompt\":\"Retell the selected text the way a pirate would.\"}]"
      }
    }
  }
}
```

`actions` / `language` と同じく、プラグインの再読み込みのたびに読み直します。`/config` で変えればすぐ反映され、`claude plugin configure` や settings.json で変えた場合は Claude Code を再起動してください。変えた後に `/quick-actions` を実行すると、無視された定義があるかとその理由を確認できます。

### ID の変更

- **`translate` → `translate-ja`**: 選択テキストを日本語に訳すアクション（🌐 日本語訳）の ID が `translate-ja` になりました。`actions` に `translate` と書いている場合は `translate-ja` に書き換えてください（書き換えないと、存在しない ID として無視され、ピン留めされなくなります）。`/quick-actions translate` も `translate-ja` に変わります（`translate` を実行すると、不明な ID として候補が表示されます）
- **外した ID**: 以前の組み込みアクションのうち、`command`, `error`, `regex`, `code-explain`, `review`, `stacktrace`, `log`, `security`, `test-ideas`, `glossary`, `simplify`, `proofread`, `structure`, `naming`, `usages`, `docs`, `next-step`, `send` はありません。`actions` に書いたままの場合は、存在しない ID と同じく無視されます（ピン留めされなくなるだけで、有効な ID が 1 つも残らなければピン留めなしになります）。近い働きのアクションが別の ID であるものもあります（例: `explain-regex`、`explain-stacktrace`、`explain-log`、`check-writing`、`find-usages`、`unit-test-ideas`、`security-check`）
- [`customActions`](#customactions) で、組み込みアクションと同じ ID のカスタム定義は無視されます。前から使っていたカスタムの ID が、新しく増えた組み込みアクションの ID と重なった場合は、カスタムの ID を変えてください（`/quick-actions` を実行すると、無視された定義とその理由を確認できます）

## コマンド

```
/quick-actions [<id> [<引数>] | hint]
```

- **`/quick-actions <id>`**: アクションを実行して、結果をペインに表示します。選択アクションは選択中のテキストに対して実行し（何も選択していなければ `選択されたテキストがありません` と答えて何も実行しません）、コンテキストアクションは選択の有無にかかわらず会話に対して、コンテキストなしアクションは選択も会話も使わずに実行します。ヒント行に並んでいないアクションも（自分で追加したものを含め）ID を指定すれば実行できます。ID の大文字小文字は区別しません
- **`/quick-actions <id> <引数>`**: コンテキストなしアクションに引数を渡します。ID の後の最初の空白より後ろ全体が引数です（前後の空白は除き、大文字小文字や途中の空白はそのまま）。例: `/quick-actions timer 5m`、`/quick-actions calc (1+2)*3`、`/quick-actions unit-convert 10 km mi`、`/quick-actions brainstorm 社内勉強会の企画`。引数の書き方と既定値は[コンテキストなしアクションの一覧](#コンテキストなしアクション単独)のとおりです。引数を省くと既定値で実行します
  - 自由テキストの引数は 500 文字までです
  - **引数を受け付けないアクションに引数を付けたとき**（選択アクション・コンテキストアクション・引数のないコンテキストなしアクション・`hint`）: 何も実行せず `<id> は引数を受け付けません: <引数>` と答えます
  - **引数の書き方が正しくないとき**（`/quick-actions timer 99h` など）: 何も実行せず `<id> の引数が正しくありません: <引数>（<書き方>）` と、書き方を添えて答えます。引数の中身をアクションが読んで初めて分かる誤り（`dice` の目の数が範囲外など）は、ペインに失敗として `引数が正しくありません: …` と表示します
- **`/quick-actions`**（ID なし）: ヒント行の ⋯ と同じダイアログ（右ペインの「アクションを選択」タブ）を開き、そこで選んだアクションを、コマンドを実行したときに選択していたテキスト（ペインを開いたまま選択し直したときは、その新しいテキスト）に対して実行します（何も選択していなければ、ダイアログにはコンテキストアクションとコンテキストなしアクションだけが並びます）
- **`/quick-actions hint`**: 選択していなくてもヒント行を開きます（[前述](#選択なしでヒント行を開くquick-actions-hint)）
- **存在しない ID**: 何も実行せず、`不明なアクション ID です: <id>（候補: …）。/quick-actions（ID なし）で一覧から検索できます` と答えます。候補は、その ID を ⋯ ダイアログの絞り込み欄に入れたときに一致するアクションを、並び順で最大 10 個です（一致するものがなければ候補は出ません）
- `customActions` で無視された定義の ID を指定したときは、何も実行せずその理由を表示します

ヒント行や ⋯ ダイアログから引数を取るコンテキストなしアクションを押したときは、[引数の入力画面](#引数の入力画面)で引数を指定できます（空欄なら既定値）。入力画面の引数は、このコマンドの引数と同じように解析・検証し、書き方が正しくないときも同じ文言のエラーを入力画面に出します。モバイルアプリなど入力欄が使えない環境では、入力画面を出さずに既定値で実行します。

`customActions` に問題があるときは、このコマンドのどの結果（ID の有無を問わず、何も選択していないときも）の末尾にも、無視した定義とその理由の一覧が付きます。

実行方式:

- **complete**: 1 回のモデル呼び出しで処理します（会話の文脈は使いません）。選択アクションは選択テキストを、コンテキストなしアクションは引数だけを渡します

- **subagent**: 専用のサブエージェントが調べて答えます。リポジトリを調べるもの（`code`・`find-usages`・`find-tests` とリポジトリ調査の `repo-` で始まるもの）は読み取り専用のツール（Read / Grep / Glob）だけを、Web を調べるもの（`web-check`・`official-docs`・`search-error`・`package-info`）は `WebSearch` / `WebFetch` だけを使います。メインの Claude からは呼ばれません
- **ローカル**: モデルを使わず、プラグインの中だけで計算します（[送信されるもの](#送信されるもの)）。結果は 20,000 文字までで、それを超える分は省いて `（以下省略）` と付けます

### コンテキストアクション

選択テキストを使わず、今の会話を対象に、セッションの fork で実行します（102 個。方式はすべて fork、モデルは会話のもの）。どれも、会話に根拠がないことは推測せず分からないと書くよう指示しています。「定番」以外のものは、ファイルの変更・コマンドの実行・ツールの使用をせず、会話に出ている内容だけから答えるよう指示しています。どれも引数は取りません。

## アクションの追加方法

[`customActions`](#customactions) の設定で、プラグインを変更せずにアクションを追加できます。ヒント行・⋯ ダイアログ・ペイン・コマンドは標準のアクションと同じように扱います。追加したアクションはヒント行（よく使う順）に並び、⋯ ダイアログから選べます（新しく追加したものは組み込みの後ろに並ぶため、一覧に収まる件数より後ろにあるあいだは、絞り込み欄に ID かラベルを入力して選びます）。その ID を `actions` に書くと先頭に固定できます。

### 設定から追加する（customActions）

[`customActions`](#customactions) の設定に、定義を JSON の配列で書きます。下の例は読みやすいよう複数行に分けています。`/config` では配列を 1 行で入力してください。

| 項目 | 必須 | 方式 | 内容 |
| --- | --- | --- | --- |
| `id` | 必須 | すべて | `actions` やコマンドに書く ID。小文字英数字を 1 つずつのハイフンでつないだもの（`review-pr`）。標準アクションの ID・`close`（✕ ボタンが使う）・`hint`（コマンドの引数）・先にあるカスタム定義の ID とは重ねられない |
| `icon` | 必須 | すべて | ヒント行に出すアイコン（絵文字 1 文字） |
| `label` | 必須 | すべて | ホバー時とペインの見出しに出す名前。両言語共通の文字列 1 つか、`{ "ja": "…", "en": "…" }` |
| `kind` | 必須 | すべて | 実行方式: `complete` / `fork` / `subagent`（標準のアクションと同じ。[アクション一覧](#アクション一覧)を参照。カスタムではローカル実行は使えない） |
| `target` | 任意 | すべて | 対象: `selection`（既定。空のときも）、`context`（選択テキストを使わず会話が対象。このとき `kind` は `fork` に限る）、`none`（コンテキストなしアクション。選択テキストも会話も使わない。このとき `kind` は `complete` か `subagent` に限る）。ヒント行では、それぞれ `[アイコン]` / `<アイコン>` / `{アイコン}` で表示する |
| `prompt` | 必須 | すべて | complete: システムプロンプト、fork: 選択テキストの後ろに続ける指示文（`target` が `context` なら指示文だけ）、subagent: サブエージェントのシステムプロンプト |
| `runningText` | 任意 | すべて | 実行中にペインに出す文言。書き方は `label` と同じ（省略時「考え中…」/「Thinking…」） |
| `model` | complete と subagent で必須 | complete, subagent | `haiku` / `sonnet` / `opus` のみ（小文字）。fork は会話のモデルを使うので無視します |
| `maxTokens` | 任意 | complete | 回答の長さの上限。1〜32000 の整数（省略時 1500） |
| `task` | subagent で必須 | subagent | サブエージェントを起動するときの依頼文の先頭。その後ろに選択テキスト（`target` が `none` なら引数。引数がなければ依頼文だけ）が付きます |
| `description` | 任意 | subagent | サブエージェントの型の説明。書き方は `label` と同じ（省略時はラベルから作る） |
| `tools` | 任意 | subagent | `Read` / `Grep` / `Glob` / `WebFetch` / `WebSearch` から選ぶ（表記どおり）。省略時は `["Read", "Grep", "Glob"]`。ほかのツールを 1 つでも書いた定義は、定義ごと無視します |

方式に関係しない項目（complete の `tools` など）や、未知の項目は無視します。

**`target` が `none` のアクションの引数**: カスタムのコンテキストなしアクションは、省略できる自由テキスト（500 文字まで）を 1 つ引数に取ります（引数の型や既定値は定義できません）。`/quick-actions <id> <引数>` で書いた引数は、complete ではユーザーの入力として、subagent では `task` の後ろに、`<input>…</input>` で囲んで渡します。ヒント行や ⋯ ダイアログから押したときは[引数の入力画面](#引数の入力画面)で引数を入力でき（既定値はないので、空欄なら引数なしと表示し、入力欄には「テキスト」と出る）、書いた引数は同じように渡します。引数がないとき（入力画面を空欄のまま実行したときや、モバイルアプリで押したときも）は、complete には入力がないことを伝える定型文だけを、subagent には `task` だけを渡します。

complete:

```json
{
  "id": "pirate",
  "icon": "🦜",
  "label": { "ja": "海賊風に言い換え", "en": "Pirate talk" },
  "kind": "complete",
  "model": "haiku",
  "maxTokens": 500,
  "prompt": "Retell the selected text the way a pirate would."
}
```

fork:

```json
{
  "id": "cause",
  "icon": "❓",
  "label": { "ja": "原因は？", "en": "What caused this?" },
  "kind": "fork",

}
```

コンテキストアクション（`target` を `context` にした fork。選択テキストは使わず、`<📣>` と表示し、選択なしで `/quick-actions hint` を実行したヒント行にも出る）:

```json
  "id": "standup",
  "icon": "📣",
  "label": { "ja": "進捗報告", "en": "Status update" },

  "prompt": "Write a short status update on this session for the team: what is done, what is in progress, and what is blocked."
}
```

コンテキストなしアクション（`target` を `none` にした complete。選択テキストも会話も使わず、`{🍳}` と表示する。`/quick-actions recipe 鶏肉 玉ねぎ` のように引数を渡せる）:

```json
{
  "id": "recipe",
  "icon": "🍳",
  "label": { "ja": "献立の案", "en": "Recipe ideas" },
  "kind": "complete",

  "model": "haiku",
  "prompt": "Suggest three simple dinner recipes. If <input> is given, it lists ingredients to use."
}
```

subagent（既定の読み取り専用ツールを明示した例。`tools` に `WebSearch` / `WebFetch` を足すと Web も調べられますが、先に下の注意を読んでください）:

```json
{
  "id": "review-pr",
  "icon": "🧪",
  "label": { "ja": "コードレビュー", "en": "Code review" },
  "kind": "subagent",

  "task": "Review the following code, reading the files around it.",
  "prompt": "You review code for bugs and risky patterns. Search with Grep and Glob, read with Read; change nothing.",
  "runningText": { "ja": "レビュー中…", "en": "Reviewing…" },
```

#### 回答言語の扱い

プロンプトには `{STYLE}` と `{ANSWER_LANGUAGE}` を文字どおり書けます。実行時に、`language` に合わせて `{STYLE}` は回答言語とペイン向けの文体の指定（`Answer in Japanese, …` / `Answer in English, …`）に、`{ANSWER_LANGUAGE}` は言語名（`Japanese` / `English`）に置き換わります。

- **complete と subagent**: `prompt` にどちらも書いていなければ、末尾に ` {STYLE}` を自動で足します。言語について何も書かなくても、表示言語で答えます。どちらかを書いていれば何も足しません（言語の指定は作者に任せます）。決まった言語で答えさせたい定義はこれを使えます（例: `"Translate the selected text into French. Write any note on it in {ANSWER_LANGUAGE}."`）
- **subagent の `task`**: プレースホルダは置き換えますが、何も足しません。回答言語の指定は `prompt`（サブエージェントのシステムプロンプト）の側に入ります
- **fork**: 標準のアクションと同じく、回答言語の指定は実行時に必ず足されます。prompt に書いた `{STYLE}` は二重にならないよう取り除き、`{ANSWER_LANGUAGE}` だけを置き換えます。そのため fork は決まった言語に固定できません

#### 不正な定義の扱い

次のような定義は、その定義だけを無視します。

- `id` がない・上の書式でない・標準アクションの ID や `close`・`hint` と重なる・先にあるカスタム定義の ID と重なる（先にある方を使う）
- 必須の項目がない・空（方式に応じた `model` / `task` を含む）、または値の形が正しくない（`label` に `ja` / `en` の片方しかない、`maxTokens` が範囲外、`tools` が空や配列でない など）
- `kind` が `complete` / `fork` / `subagent` 以外、`model` が `haiku` / `sonnet` / `opus` 以外
- `target` が `selection` / `context` / `none`（小文字）以外、`target` が `context` なのに `kind` が `fork` 以外、または `target` が `none` なのに `kind` が `fork`（例: `target は selection / context / none のいずれかにしてください（指定: foo）`、`target が context の定義は kind を fork にしてください（指定: complete）`、`target が none のアクションは complete か subagent で書いてください（指定: fork）`）
- `tools` に上の 5 つ以外のツールがある。そのツールだけ外して動かすと作者の意図と違う動きになるため、定義ごと無視します

設定が JSON として読めないとき、または配列でないときは、カスタム定義をすべて無視します。settings.json では値を文字列（配列を引用符で囲み、中の引用符をエスケープしたもの）で書いてください。引用符で囲まない配列を書くと、Claude Code がプラグインを読み込みません。どの場合も標準のアクションはそのまま動きます。無視した定義と理由は次の方法で確認できます。

- **`/quick-actions` を実行する**（ID の有無は問わず、何も選択していなくてもよい。ID なしでは ⋯ ダイアログも開く）: 結果の末尾に、問題が 1 件 1 行で並びます（例: `#3 (review-pr): subagent で使えないツール Bash を指定しています（…）`）。番号は配列の中の位置で、1 から数えます。この方法はいつでも使えます
- セッションの開始時に、件数と 1 件目の問題をトーストで知らせます。セッション中に `/config` で変えた場合は、次のセッションまでトーストが出ないことがあります。`/quick-actions` で確認してください
- ペインが開いているときは、その先頭にも失敗の色で一覧が出ます

#### ツールについての注意

- `WebFetch` / `WebSearch` を許すと、サブエージェントは選択テキストや引数、`Read` / `Grep` / `Glob` で読んだ内容（リポジトリに限らず、Claude Code の権限設定で読めるファイルすべて）を外部のサイトへ送り得ます。自分の判断で送ることも、選択テキストに書かれた指示（プロンプトインジェクション。選択テキストは `<selected>…</selected>` で囲んでいるだけです）に誘導されて送ることもあります。信頼できるテキストに使うアクションに限って許し、それ以外は既定の読み取り専用ツールのままにしてください
- コマンドの実行やファイルの変更ができるツール（`Bash` / `Write` / `Edit` など）は、`customActions` では受け付けません

### 組み込みアクションとカタログページ

[アクション一覧ページ](https://imahiro-t.github.io/quick-actions/?lang=ja)（`docs/index.html`）はビルド不要の静的ページです。データの `docs/actions-data.js` は `hooks/actions.ts` の定義から生成し、手では書きません。

- `ACTIONS` の組み込みアクションを追加・変更したら、`category`（`hooks/catalog.ts` の `CATEGORIES` のいずれかの ID。アクションと同じ種類のもの）と `summary`（上の表と同じ 1 行説明。`{ ja, en }`）を書きます
- そのうえでリポジトリのルートで `node scripts/gen-catalog.mjs` を実行してデータを再生成し、`docs/actions-data.js` をコミットします。スクリプトには Node 24 以上が必要です（TypeScript のソースをそのまま読み込むため）。asdf なら例えば `ASDF_NODEJS_VERSION=24.21.0 node scripts/gen-catalog.mjs`
- 再生成を忘れると、`tests/catalog.test.ts`（`claude plugin test .` で実行）が落ちます。カテゴリや説明のない組み込みアクションや、種類の違うカテゴリに入れたアクションがあっても落ちます
